# Supabase セットアップ手順

ひろば掲示板を Supabase につなぐための手順です。所要時間は 15〜20 分ほどです。
(Supabase の画面の文言は更新されることがあります。少し違っていても、近い項目を探してください)

## 全体像

```
ブラウザ(GitHub Pages) ──▶ Supabase(Postgres + 認証)
   index.html / app.js          テーブル + 関数(schema.sql)
   store.js
```

- 投稿・アカウント・ポイントは Supabase に保存され、全員で共有されます。
- ポイント計算・権限チェック・NGワード判定は **サーバー側の関数**で行うので、ブラウザ側では改ざんできません。
- テーブルへの直接アクセスは禁止してあり、公開してよい鍵(anon キー)が漏れても、関数で許可した操作しかできません。

## 1. アカウントとプロジェクトを作る

1. https://supabase.com にアクセスし、**Start your project** からアカウントを作成する(GitHub アカウントでのログインも可)
2. **New project** を押して、次のように入力する
   - **Name**: `hiroba-keijiban`(何でもよい)
   - **Database Password**: **Generate a password** で自動生成し、パスワード管理ツールなどに控えておく
   - **Region**: `Northeast Asia (Tokyo)`
   - プランは **Free** でよい
3. 1〜2 分待って、プロジェクトの準備が完了するのを待つ

> 無料プランでは、**1 週間ほど誰もアクセスしないとプロジェクトが一時停止**されます(ダッシュボードから再開できます)。

## 2. データベースを作る(SQL を実行)

1. 左メニューの **SQL Editor** を開き、**New query** を押す
2. このフォルダの [`schema.sql`](schema.sql) を開き、**全文をコピーして貼り付ける**
3. **Run** を押す。`Success. No rows returned` と出れば成功
   - 何度実行しても安全な書き方になっています(データは消えません)。後でルールを変えたときは、書き換えて再実行してください

## 3. 認証の設定

左メニューの **Authentication** で、次の 3 か所を設定します。

### (a) メール確認 — **Sign In / Providers → Email**

| 設定 | おすすめ | 意味 |
|---|---|---|
| **Confirm email** | 本番運用は **ON** | 登録時に確認メールのリンクを開かないとログインできない。実在するメールアドレスだけが登録でき、ポイント目当ての使い捨てアカウントを減らせる |
| | 試すだけなら **OFF** | 登録するとすぐにログインできる |

> ON にした場合、無料の標準メール送信は**送信数の上限が小さい**です(1 時間に数通)。利用者が増えたら、独自の SMTP(Resend など)を設定してください。

### (b) パスワードの長さ — 同じ画面

**Minimum password length** を **8** にする(画面側も 8 文字以上を求めています)。

### (c) URL — **URL Configuration**

- **Site URL**: `https://just-jump852.github.io/keijiban/`
- **Redirect URLs** に次を追加する
  - `https://just-jump852.github.io/keijiban/`
  - (手元で試すなら)`http://localhost:5180/`

メール確認のリンクは、ここで許可した URL にしか戻れません。設定しないと、確認後に別のページへ飛んでしまいます。

## 4. 接続情報を `config.js` に書く

1. 左下の **Project Settings**(歯車)→ **API**(または画面上部の **Connect**)を開く
2. 次の 2 つをコピーする
   - **Project URL** … `https://xxxxxxxxxxxx.supabase.co`
   - **anon public** キー(新しい画面では **Publishable key** `sb_publishable_...`)
3. [`../config.js`](../config.js) の空欄に貼り付ける

```js
window.KEIJIBAN_CONFIG = {
  supabaseUrl: 'https://xxxxxxxxxxxx.supabase.co',
  supabaseAnonKey: 'sb_publishable_xxxxxxxxxxxxxxxx',
};
```

> ⚠️ **`service_role` キー / `secret` キーは絶対に貼らないでください。** 全データを自由に読み書きできる強い権限を持つ鍵です。
> anon / publishable キーは、ブラウザに渡ることを前提にした「公開してよい鍵」なので、GitHub に置いても問題ありません。

## 5. 最初にご自身で登録する(管理者になります)

**最初に登録した人が管理者**になります(通報の確認・NGワードの編集ができます)。
サイトの URL を他の人に教える**前に**、必ずご自身で登録してください。

管理者を別の人に付け替えるときは、SQL Editor で実行します。

```sql
update public.profiles set is_admin = (nickname = '管理者にしたい人のニックネーム');
```

## 6. 動作確認

- [ ] 新規登録できる(+10pt)
- [ ] スレッドを立てられる(+5pt)・返信できる(+2pt)
- [ ] 別のブラウザ(またはシークレットウィンドウ)で別アカウントを作ると、最初のアカウントの投稿が見える
- [ ] 別アカウントで「いいね」「ベストアンサー」を試すと、相手のポイントが増える
- [ ] 管理者アカウントに「管理」メニューが出る

## 運用メモ

- **ポイントのルールを変える**: `schema.sql` の `rule_pts()` と、`store.js` の `RULES`(画面表示用)を**同じ値**にして、schema.sql を再実行する
- **投稿を消したい**: 管理画面の「非表示」を使う(通報された投稿が対象)。完全に消すときは Supabase の **Table Editor** から `posts` / `threads` を削除する
- **バックアップ**: 無料プランの自動バックアップは限定的です。大事になってきたら、**Database → Backups** を確認してください
- **個人情報**: メールアドレスは Supabase の認証側に保存され、他のユーザーには見えません。掲示板には個人情報を書き込まないよう、利用者にも案内してください
- **うまくいかないとき**: ブラウザの開発者ツール(F12)の **Console** と、Supabase の **Logs** を確認してください
