# Supabase セットアップ手順

ひろば掲示板を Supabase につなぐための手順です。所要時間は 15〜20 分ほどです。
(Supabase の画面の文言は更新されることがあります。少し違っていても、近い項目を探してください)

## 全体像

```
ブラウザ(GitHub Pages) ──▶ Supabase(Postgres + 認証)
   index.html / app.js          テーブル + 関数(schema.sql)
   store.js
```

- 投稿・アカウント・ポイントは Supabase に保存され、全員で共有されます。
- ポイント計算・権限チェック・NGワード判定は **サーバー側の関数**で行うので、ブラウザ側では改ざんできません。
- テーブルへの直接アクセスは禁止してあり、公開してよい鍵(anon / publishable キー)が漏れても、関数で許可した操作しかできません。
- ログインは **メールアドレス+パスワード**(登録時にメールの確認リンクで認証)です。

## 1. アカウントとプロジェクトを作る

1. https://supabase.com にアクセスし、**Start your project** からアカウントを作成する(GitHub アカウントでのログインも可)
2. **New project** を押して、次のように入力する
   - **Name**: `hiroba-keijiban`(何でもよい)
   - **Database Password**: **Generate a password** で自動生成し、パスワード管理ツールなどに控えておく
   - **Region**: `Northeast Asia (Tokyo)`
   - プランは **Free** でよい
3. 1〜2 分待って、プロジェクトの準備が完了するのを待つ

> 無料プランでは、**1 週間ほど誰もアクセスしないとプロジェクトが一時停止**されます(ダッシュボードから再開できます)。

## 2. データベースを作る(SQL を実行)

1. 左メニューの **SQL Editor** を開き、**New query** を押す
2. このフォルダの [`schema.sql`](schema.sql) を開き、**全文をコピーして貼り付ける**
3. **Run** を押す。`Success. No rows returned` と出れば成功
   - 「破壊的な操作を含む」という確認が出ますが、これは中の `drop trigger if exists` などに反応した警告です。新しいプロジェクトなら失うデータはないので、続行して構いません
   - 何度実行しても安全な書き方になっています(データは消えません)。後でルールを変えたときは、書き換えて再実行してください

## 3. 認証の設定(メールアドレス+パスワード)

左メニューの **Authentication** で設定します。

### (a) Sign In / Providers

1. **Allow new users to sign up** を **ON**
2. **Confirm email** を **ON**(登録時に確認メールのリンクを開かないとログインできない。実在するメールアドレスだけが登録でき、使い捨てアカウントによるポイント稼ぎを減らせる)
3. **Allow anonymous sign-ins** を **OFF**(メールなしのアカウントを作れないようにする)
4. **Auth Providers → Email** を開き、**Enable email provider** を **ON**、**Minimum password length** を **8** にして **Save**

### (b) URL Configuration

- **Site URL**: `https://just-jump852.github.io/keijiban/`
- **Redirect URLs** に同じ URL を追加する(手元で試すなら `http://localhost:5180/` も)

メールのリンクは、ここで許可した URL にしか戻れません。設定しないと、確認後に別のページへ飛んでしまいます。
パスワードの再設定メールも、同じ URL に戻ります(同じブラウザで開くと、新しいパスワードの入力画面が開きます)。

### (c) メールの送信について(重要)

Supabase が無料で使える標準のメール送信は、**送信数の上限がとても小さい**(1 時間に数通程度)うえ、迷惑メールに入りやすいです。
登録者が増えると、確認メールが届かなくなります。人が増えてきたら、**独自の SMTP**(Resend、SendGrid、Amazon SES など)を
**Authentication → Emails → SMTP Settings** に設定してください。
(**Authentication → Rate Limits** で、現在の上限を確認できます)

メールの文面は **Authentication → Emails → Templates** で日本語に変更できます(件名と本文)。

## 4. 接続情報を `config.js` に書く

1. 左下の **Project Settings**(歯車)→ **API Keys** を開く
2. 次の 2 つをコピーする
   - **Project URL** … `https://xxxxxxxxxxxx.supabase.co`(プロジェクトの ID から作られる)
   - **Publishable key**(`sb_publishable_...`。古い画面では **anon public** キー)
3. [`../config.js`](../config.js) の空欄に貼り付ける

```js
window.KEIJIBAN_CONFIG = {
  supabaseUrl: 'https://xxxxxxxxxxxx.supabase.co',
  supabaseAnonKey: 'sb_publishable_xxxxxxxxxxxxxxxx',
};
```

> ⚠️ **`service_role` キー / `secret` キーは絶対に貼らないでください。** 全データを自由に読み書きできる強い権限を持つ鍵です。
> anon / publishable キーは、ブラウザに渡ることを前提にした「公開してよい鍵」なので、GitHub に置いても問題ありません。

## 5. 最初にご自身で新規登録する(管理者になります)

**最初に新規登録した人が管理者**になります(通報の確認・NGワードの編集ができます)。
サイトの URL を他の人に教える**前に**、必ずご自身で登録・メール認証まで済ませてください。

管理者を別のアカウントに付け替えるときは、SQL Editor で実行します。

```sql
-- 管理者にしたい人のニックネームを指定する(他の人は管理者でなくなる)
update public.profiles set is_admin = (nickname = '管理者にしたい人のニックネーム');
```

### 以前の「ニックネームだけ」で作ったアカウントがある場合

メールを持たない匿名アカウントは、**マイページ →「アカウントの登録」**からメールアドレスとパスワードを登録すると、
ポイントや管理者権限を保ったまま、正式なアカウントに切り替えられます(確認メールのリンクを開くと完了)。
登録しないままログアウトすると、そのアカウントには戻れません。

## 6. 動作確認

- [ ] 新規登録すると確認メールが届き、リンクを開いてからログインできる(+10pt)
- [ ] スレッドを立てられる(+5pt)・返信できる(+2pt)
- [ ] 別のブラウザ(またはシークレットウィンドウ)で別アカウントを作ると、最初のアカウントの投稿が見える
- [ ] 別アカウントで「いいね」「ベストアンサー」を試すと、相手のポイントが増える
- [ ] マイページでニックネーム・パスワードを変更できる
- [ ] 「パスワードを忘れた方」から再設定メールが届き、新しいパスワードを設定できる
- [ ] 管理者アカウントに「管理」メニューが出る

## 運用メモ

- **ポイントのルールを変える**: `schema.sql` の `rule_pts()` と、`store.js` の `RULES`(画面表示用)を**同じ値**にして、schema.sql を再実行する
- **投稿を消したい**: 管理画面の「非表示」を使う(通報された投稿が対象)。完全に消すときは Supabase の **Table Editor** から `posts` / `threads` を削除する
- **アカウントを消したい**: **Authentication → Users** から該当ユーザーを削除する(プロフィール・投稿も連動して消える)
- **バックアップ**: 無料プランの自動バックアップは限定的です。大事になってきたら、**Database → Backups** を確認してください
- **個人情報**: メールアドレスは Supabase の認証側に保存され、他のユーザーには見えません。掲示板には個人情報を書き込まないよう、利用者にも案内してください
- **うまくいかないとき**: ブラウザの開発者ツール(F12)の **Console** と、Supabase の **Logs** を確認してください
